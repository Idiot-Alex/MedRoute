# 接口设计

## 1. 适用范围

本文定义 MedRoute 第一版用户导航 API 和维护端 API 契约，并以
`09-多楼层导航实施方案.md` 为上位约束。

> 当前实现状态（2026-07-26）：正式导航已读取 PostgreSQL 当前发布图；
> `navigation-context`、POI、路线、底图读取及第 5 节的维护 MVP 均已实现。
> 当前保留的数字 ID `GET` 接口仅供单层 Demo 兼容。正式认证和数据范围授权
> 仍是生产化待办。

第一版明确：

- 路线计算范围是单个楼栋；暂不支持跨楼栋或院区室外路线。
- 用户端只读取已发布版本，维护端只编辑草稿版本。
- 路线由后端权威计算，前端不自行拼接跨层连接。
- 所有路线响应都返回实际使用的 `releaseId`。
- 地图图数据按发布版本读取，路线按楼层分段并显式返回跨层动作。

## 2. 通用约定

### 2.1 URL 与媒体类型

- 基础路径：`/api`
- 请求和响应：`application/json; charset=utf-8`
- 图片上传接口除外，使用 `multipart/form-data`
- URL 中使用复数资源名，不使用结尾 `/`

### 2.2 ID 与业务编码

- 所有 API `id` 字段都是字符串形式的 UUID，对应数据库 `public_id`。
- `code` 是人可读业务编码，例如 `1F`、`P-PHARMACY`、`ELEV-A`。
- 客户端保存和传递关系时使用 `id`，不能把 `code` 当成全局唯一 ID。
- API 绝不暴露数据库 `BIGINT` 自增主键。
- 图元素的公开 ID 在复制发布版本时可以保持稳定，但它的权威归属始终由 `releaseId` 限定。

示例：

```json
{
  "id": "eae9d388-3857-4ca4-8852-44518e846c9a",
  "code": "ELEV-A",
  "name": "A 电梯"
}
```

### 2.3 单位、坐标与时间

- `distanceMeters`：米，可含小数。
- `timeSeconds`、`estimatedSeconds`：整数秒。
- `x`、`y`：楼层图片像素坐标，原点为图片左上角。
- 时间使用 ISO-8601 UTC，例如 `2026-07-25T06:30:00Z`。
- 字段名必须带单位，不再使用含义不明确的 `distance`、`walkTime` 或 `estimatedTime`。

### 2.4 列表与分页

可能增长的列表统一返回：

```json
{
  "items": [],
  "nextPageToken": null
}
```

请求参数：

- `pageSize`：默认 `50`，最大 `200`。
- `pageToken`：服务端签发的不透明字符串，客户端不得解析。

楼层、楼栋等天然小列表也保留相同的 `items` 外层，但可以不分页。

### 2.5 请求追踪

- 服务端接受或生成 `X-Request-Id`。
- 响应头和错误体均返回同一个 `requestId`。
- 客户端不得把 `requestId` 当成业务资源 ID。

## 3. 标准错误模型

所有非 2xx 响应使用统一结构：

```json
{
  "error": {
    "code": "RELEASE_MISMATCH",
    "message": "楼栋地图已更新，请刷新后重试。",
    "requestId": "req-01J3QW7H8BDP5X4D5Y3NQ9K4MW",
    "timestamp": "2026-07-25T06:30:00Z",
    "path": "/api/routes",
    "details": [
      {
        "field": "expectedReleaseId",
        "reason": "expected REL-OLD but active release is REL-NEW"
      }
    ]
  }
}
```

`message` 可直接展示给用户；客户端分支判断必须使用稳定的 `code`。

| HTTP | 错误码 | 含义 |
|---|---|---|
| `400` | `INVALID_ARGUMENT` | JSON、必填字段、UUID、枚举或时间范围非法 |
| `401` | `UNAUTHENTICATED` | 未登录或凭据失效 |
| `403` | `FORBIDDEN` | 无数据范围、发布、运营或员工路线权限 |
| `404` | `RESOURCE_NOT_FOUND` | 指定资源不存在 |
| `404` | `MAP_RELEASE_NOT_PUBLISHED` | 楼栋没有启用中的发布版本 |
| `405` | `METHOD_NOT_ALLOWED` | 请求方法不受支持 |
| `406` | `NOT_ACCEPTABLE` | 无法生成客户端要求的响应媒体类型 |
| `409` | `RELEASE_MISMATCH` | 客户端期望版本与当前启用版本不同 |
| `409` | `DRAFT_CHANGED` | 草稿并发修改，`If-Match` 已过期 |
| `409` | `RELEASE_IMMUTABLE` | 尝试修改已发布或已退役版本 |
| `409` | `OPERATION_CONFLICT` | 发布、回滚或覆盖操作与当前状态冲突 |
| `415` | `UNSUPPORTED_MEDIA_TYPE` | 请求媒体类型不受支持 |
| `422` | `POI_NOT_IN_RELEASE` | POI 不属于本次路线使用的发布版本 |
| `422` | `ROUTE_UNREACHABLE` | 当前模式和运营状态下无可用路线 |
| `422` | `VALIDATION_FAILED` | 草稿未通过发布前校验 |
| `500` | `INTERNAL_ERROR` | 未预期服务端错误 |

不可达是可预期业务结果，使用 `422 ROUTE_UNREACHABLE`，不能返回空路径假装成功。

## 4. 用户导航 API

用户导航 API 只能访问 `published` 版本，不能通过猜测 `releaseId` 读取草稿。

### 4.1 查询医院列表

```http
GET /api/hospitals
```

响应：

```json
{
  "items": [
    {
      "id": "bcf283ec-9e96-43c2-9088-0f6269d804cb",
      "code": "HOSP-SH-001",
      "name": "测试医院",
      "city": "上海"
    }
  ],
  "nextPageToken": null
}
```

### 4.2 查询医院下的楼栋

```http
GET /api/hospitals/{hospitalId}/buildings?campusId={campusId}
```

`campusId` 可选。响应中显式包含院区，避免客户端把同名楼栋混在一起：

```json
{
  "items": [
    {
      "id": "cd61a4d6-3dd7-44d2-b389-fccd995572bf",
      "code": "OUTPATIENT",
      "name": "门诊楼",

        "id": "895b4c0f-2798-4f68-8480-71102776b82a",
        "code": "MAIN",
        "name": "本部院区"
      },
      "navigationAvailable": true
    }
  ],
  "nextPageToken": null
}
```

### 4.4 查询当前版本的 POI

```http
GET /api/buildings/{buildingId}/pois?keyword=药房&floorId={floorId}&category=pharmacy
```

`floorId`、`category` 可选。服务端只搜索当前启用版本：

```json
{
  "releaseId": "db599d03-ef8e-4f13-9545-b579c5d3f5d6",
  "items": [
    {
      "id": "ae464da6-3913-4b45-ab80-470d50435821",
      "code": "P-PHARMACY",
      "name": "药房",
      "category": "pharmacy",

      "floorCode": "1F",
      "x": 800,
      "y": 390,
      "accessible": true
    }
  ],
  "nextPageToken": null
}
```

POI 搜索响应中的 `releaseId` 必须与导航上下文一致。若客户端发现不同，应刷新导航上下文。

### 4.6 路线规划

```http
POST /api/routes
Content-Type: application/json
```

请求：

```json
{
  "buildingId": "cd61a4d6-3dd7-44d2-b389-fccd995572bf",
  "expectedReleaseId": "db599d03-ef8e-4f13-9545-b579c5d3f5d6",
  "startPoiId": "5e683d1e-0d11-46a7-8438-0f6fc4daf8f6",
  "endPoiId": "ae464da6-3913-4b45-ab80-470d50435821",
  "routeMode": "accessible"
}
```

字段规则：

- `buildingId`、`startPoiId`、`endPoiId`、`routeMode` 必填。
- `expectedReleaseId` 可选但强烈建议传入。传入后若不等于当前启用版本，
  返回 `409 RELEASE_MISMATCH`，错误详情的 `reason` 包含当前启用版本 ID。
- 起点和终点必须属于该楼栋当前启用版本。
- `startPoiId` 和 `endPoiId` 必须不同。
- `normal` 只使用开放的 `accessScope = public` 边。
- `accessible` 排除楼梯、不可无障碍通行的边和不可用电梯。
- `staff` 可使用 `public` 和 `staff` 边，但仅对具有员工路线权限的身份开放；普通用户传入该值返回 `403 FORBIDDEN`。

第一版公共客户端只显示 `normal`、`accessible`。`less_elevator` 在定义明确的成本规则和测试前不进入正式契约。

### 4.7 版本切换处理

推荐客户端顺序：

1. 调用 `navigation-context` 得到 `releaseId` 和楼层图片。
2. 查询同一版本的 POI。
3. 调用路线接口并传入 `expectedReleaseId`。
4. 使用响应中的 `releaseId` 请求各楼层 graph。

若返回 `RELEASE_MISMATCH`，客户端清空旧地图和 POI 缓存，重新从第一步加载。不得把旧版本 POI 与新版本路线混用。

## 5. 维护端 API

维护端统一位于 `/api/admin`。生产环境必须鉴权并执行医院/院区/楼栋数据范围
校验；当前本地 MVP 的 `X-Admin-User` 仅用于记录操作人，不构成身份认证。

### 5.1 草稿版本

```http
POST /api/admin/buildings/{buildingId}/releases/drafts
GET  /api/admin/buildings/{buildingId}/releases
GET  /api/admin/releases/{releaseId}
DELETE /api/admin/releases/{releaseId}
```

创建草稿请求：

```json
{
  "code": "DRAFT-2026-002",
  "basedOnReleaseId": "db599d03-ef8e-4f13-9545-b579c5d3f5d6",
  "description": "增加 3F 影像科并调整 A 电梯停靠。"
}
```

返回：

```json
{
  "id": "6d40cf5e-45c8-42a4-80f4-616615992f78",
  "code": "DRAFT-2026-002",
  "status": "draft",
  "contentRevision": 0
}
```

复制草稿时，楼层图片绑定和全部图元素在同一事务中复制。语义未变化的元素保留公开 ID。

### 5.2 楼层图片修订与绑定

```http
POST /api/admin/releases/{releaseId}/floors/{floorId}/map
```

上传接口使用 `multipart/form-data`，包含：

- `file`

服务端读取并校验真实格式和图片宽高，计算 SHA-256，创建不可变修订版并绑定到
同一草稿。新旧底图尺寸不同时，服务端按宽高比例缩放该层节点和 POI 坐标。

### 5.3 图元素维护

当前少量维护人员 MVP 以完整工作区快照保存，且仅接受 `draft` 版本：

```http
PUT /api/admin/releases/{releaseId}/workspace
```

请求体包含该发布版本的 `nodes`、`edges`、`pois`、`connectors`、
`connectorStops` 和 `verticalLinks` 六组数组。后续维护人员并发增加时，再拆分
为逐元素写接口；当前完整快照配合乐观锁更简单且符合运维规模。

每个草稿详情响应返回：

```http
ETag: "17"
```

所有草稿修改、删除、校验和发布请求必须带：

```http
If-Match: "17"
```

每次成功修改后 `contentRevision` 加一，并在响应的新 `ETag` 中返回。版本不符返回 `409 DRAFT_CHANGED`。已发布版本上的任何写操作返回 `409 RELEASE_IMMUTABLE`。

### 5.4 校验与发布

```http
POST /api/admin/releases/{releaseId}/validate
POST /api/admin/releases/{releaseId}/publish
POST /api/admin/releases/{targetReleaseId}/rollback
```

校验响应：

```json
{
  "releaseId": "6d40cf5e-45c8-42a4-80f4-616615992f78",
  "contentRevision": 17,
  "passed": false,
  "errors": [
    {
      "code": "CONNECTOR_STOP_NOT_LINKED",
      "elementType": "connector_stop",
      "elementId": "6efbf041-11ba-4a36-b68c-e07b407ccbbf",
      "message": "A 电梯 3F 停靠点未配置任何可通行跨层连接。"
    }
  ],
  "warnings": []
}
```

发布请求：

```json
{
  "reason": "完成现场复核，发布三层门诊楼地图。"
}
```

发布要求：

- 最新校验结果必须是同一 `contentRevision` 且已通过。
- 发布和启用版本切换在一个事务中完成。
- 成功返回 `200` 和新的 navigation context；图缓存提交后失效。
- 不满足条件返回 `422 VALIDATION_FAILED` 或 `409 DRAFT_CHANGED`。

回滚请求：

```json
{
  "reason": "新版本 3F 图片与现场不一致。"
}
```

目标必须是同一楼栋既有的已发布版本。回滚只切换启用版本，不修改历史数据。

### 5.5 临时运营覆盖

```http
GET    /api/admin/buildings/{buildingId}/operations/closures
POST   /api/admin/buildings/{buildingId}/operations/closures
DELETE /api/admin/operations/closures/{closureId}
```

创建请求：

```json
{
  "targetType": "vertical_connector",
  "targetId": "8d112ad2-fcbf-434b-a1a2-aea550e40b4d",
  "effectiveFrom": "2026-07-25T06:30:00Z",
  "effectiveTo": "2026-07-25T12:30:00Z",
  "reason": "A 电梯检修"
}
```

创建时目标必须属于该楼栋的当前启用版本。覆盖只影响在有效期内新计算的路线。

撤销通过 `DELETE` 完成，并记录撤销人和时间。当前后台创建立即生效的封闭，
API 可传入有效起止时间。

覆盖和撤销均保留操作人、时间和原因，不提供物理删除接口。

## 6. 鉴权与数据范围

建议最小角色：

| 权限 | 能力 |
|---|---|
| `NAVIGATION_READ` | 读取已发布地图、POI 和普通/无障碍路线 |
| `STAFF_ROUTE_READ` | 在授权楼栋请求 `staff` 路线 |
| `MAP_EDITOR` | 在授权楼栋编辑草稿和执行校验 |
| `MAP_PUBLISHER` | 发布和回滚授权楼栋版本 |
| `OPERATION_OPERATOR` | 创建、查询和撤销授权楼栋的临时覆盖 |

规则：

- 维护端 API 至少要求登录，不允许匿名调用。
- 权限判断同时检查角色和医院/院区/楼栋数据范围。
- `routeMode = staff` 必须由服务端身份权限决定，不能信任前端模式字符串。
- 发布人与编辑人可以是同一人，但生产环境建议保留可配置的复核流程。
- 用户导航 API 是否允许匿名由部署环境决定；即使匿名，也只能读取已发布数据。

## 7. 缓存与一致性

- `navigation-context` 代表当前指针，使用短缓存或条件请求。
- `/api/releases/{releaseId}/...` 内容不可变，可长期缓存。
- 路线结果不跨请求缓存临时覆盖状态；若将来缓存，缓存键必须至少包含 `releaseId`、起终点、模式和覆盖状态版本。
- 发布事务提交后再失效楼栋当前版本缓存，不能让客户端看见半发布状态。
- 路线请求先固定 `releaseId`，再读取图和覆盖；同一请求内不得跨版本读取。

## 8. 被替代的旧契约

以下旧设计不再作为正式接口：

```text
GET /api/hospitals/{hospitalId}/floors/{floorId}/map
GET /api/hospitals/{hospitalId}/floors/{floorId}/graph
POST /api/routes 仅传 hospitalId
路线响应只返回扁平 path
使用 P2、N1 与数据库数字 ID 混合作为 id
```

后续实现应以本文契约生成 OpenAPI 文档，并在 API 契约测试中固定字段名、单位、错误码和权限边界。
