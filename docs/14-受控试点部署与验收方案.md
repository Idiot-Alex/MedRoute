# 受控试点部署与验收方案

## 1. 适用范围

本方案用于医院内网中的单机技术试点：维护人员在部署电脑上编辑地图，普通用户
通过同一局域网中的手机只读导航。当前维护 API 尚未接入正式登录，因此该部署
不能直接作为公网生产环境。

试点运行使用构建后的 Vue/OpenLayers 前端和容器化 Spring Boot，不依赖宿主机
安装 JDK、Node.js 或 pnpm；启动服务只需 Docker Desktop。执行第 4 节的自动
验收脚本还需要 Node.js 24 LTS。后端使用 Spring Boot 3.5 长期维护线和
Java 17。

## 2. 部署拓扑

```text
手机浏览器
  -> http://电脑局域网IP:8088
  -> Nginx 导航站点
  -> 公开 API 白名单
  -> Spring Boot（仅 Compose 内部网络）

部署电脑浏览器
  -> http://127.0.0.1:8089
  -> Nginx 维护站点
  -> 完整维护 API
  -> Spring Boot（仅 Compose 内部网络）

Spring Boot
  -> PostgreSQL 16 数据卷
```

| 端口 | 监听范围 | 用途 |
| --- | --- | --- |
| `8088` | 全部网卡 | 手机导航和公开只读 API |
| `8089` | `127.0.0.1` | 电脑维护后台和完整维护 API |
| `5432` | `127.0.0.1` | 本机数据库维护和开发 |
| `8080` | 不映射 | Spring Boot，仅容器内部访问 |

`8088` 只转发以下接口：

```http
GET  /api/buildings/{buildingId}/navigation-context
GET  /api/buildings/{buildingId}/pois
POST /api/routes
GET  /api/map-images/{revisionId}
```

公开入口中的 `/api/admin` 和其他未列出的 `/api` 均返回 JSON `404`。维护入口
还会拒绝非本机网页 Origin；该限制只是登录接入前的额外防护，不能替代身份认证。

## 3. 启动

先停止 IDEA 中运行的后端，避免两个应用实例同时修改同一数据库。然后在仓库
根目录执行：

```bash
docker compose --profile pilot up -d --build
docker compose --profile pilot ps
```

三个服务均应显示 `healthy`：

```text
postgres
navigation-server
pilot-gateway
```

查看电脑局域网 IP：

```bash
ifconfig en0
```

手机和电脑必须连接允许设备互访的同一网络。假设电脑 IP 为 `192.168.5.42`：

- 手机导航：<http://192.168.5.42:8088/>
- 电脑维护：<http://127.0.0.1:8089/?navigation=http%3A%2F%2F192.168.5.42%3A8088%2F>

维护地址中的 `navigation` 参数用于生成手机可访问的固定点二维码。不要把
`127.0.0.1` 写进二维码导航基础地址。

## 4. 自动验收

从局域网公开入口检查三层上下文、30 个 POI 和 58 条普通/无障碍路线：

```bash
MEDROUTE_API_BASE=http://192.168.5.42:8088 \
  MEDROUTE_EXPECTED_POI_COUNT=30 \
  node scripts/pilot-api-smoke.mjs --public-only
```

从仅本机维护入口检查版本、二维码和可逆设施封闭：

```bash
MEDROUTE_API_BASE=http://127.0.0.1:8089 \
  MEDROUTE_NAVIGATION_BASE_URL=http://192.168.5.42:8088/ \
  MEDROUTE_EXPECTED_POI_COUNT=30 \
  node scripts/pilot-api-smoke.mjs --write
```

使用真实 PNG/JPEG 检查底图上传、坐标缩放、保存、关键路线和草稿清理：

```bash
MEDROUTE_API_BASE=http://127.0.0.1:8089 \
  MEDROUTE_MAP_IMAGE=/path/to/replacement.jpg \
  MEDROUTE_FLOOR_CODE=1F \
  node scripts/pilot-authoring-smoke.mjs
```

负向边界至少检查：

```bash
curl -i \
  http://192.168.5.42:8088/api/admin/buildings/00000000-0000-0000-0000-000000000100/releases
nc -vz 192.168.5.42 8080
nc -vz 192.168.5.42 5432
```

预期分别为 `404`、连接失败、连接失败。

## 5. 停止与切换

只停止试点应用、保留 PostgreSQL 供 IDEA 开发：

```bash
docker compose --profile pilot stop pilot-gateway navigation-server
```

随后可在 IDEA 运行 `HospitalNavigationApplication`，并使用 `pnpm dev:admin`
和 `pnpm dev:navigation` 启动开发前端。不要同时运行 IDEA 后端和试点后端。

重新启动试点：

```bash
docker compose --profile pilot up -d
```

停止全部容器但保留数据库卷：

```bash
docker compose --profile pilot down
```

不要添加 `-v`，否则会删除 PostgreSQL 数据卷。

## 6. 数据保护

试点前和每次正式建图后执行：

```bash
scripts/backup-postgres.sh
```

备份必须复制到另一块磁盘或受控对象存储，并保留 `.sha256`。至少完成一次独立
数据库恢复演练：

```bash
scripts/restore-postgres.sh backups/<backup>.dump medroute_restore_drill
```

## 7. 转正式环境前的门禁

- 使用取得授权的医院底图，并由医院人员完成逐层现场走查。
- 完成实际手机、医院网络和宿主 App WebView 验收。
- 接入宿主项目的登录、管理员角色和医院/楼栋数据权限。
- 使用 HTTPS 域名、受控反向代理、防火墙和强数据库密码。
- 配置每日异机备份、恢复演练、运行监控和告警。

技术自动验收通过只说明系统闭环可用，不代表测试点位已经成为医院正式导诊数据。
