# 地图维护与发布操作手册

## 1. 使用范围

本手册适用于 MedRoute 当前轻量版本。系统面向少量地图维护人员和大量只读导航
用户，以楼栋完整导航图为发布单位。每层可以使用不同底图，电梯和楼梯的停靠层
及层间连接必须逐项标注，系统不会推断“同一电梯一定到达所有楼层”。

用户导航主要在手机浏览器使用，地图和路径维护主要在电脑浏览器使用。维护后台
最低按 `1200 x 720` 验收，推荐 `1440 x 900`；完整终端边界见
[终端体验与前端实施边界](./11-终端体验与前端实施边界.md)。

## 2. 本地启动

### 2.1 前置环境

- JDK 17。项目以 Java 17 为编译基线。
- Docker Desktop。
- Node.js 20 和 pnpm 10，用于新版 Vue/OpenLayers 前端。
- Python 3，仅在复核静态兼容页面时需要。

### 2.2 启动 PostgreSQL

在仓库根目录执行：

```bash
docker compose up -d postgres
docker compose ps
```

首次启动会创建 `medroute` 数据库。后端启动时 Flyway 自动执行迁移并初始化
三层基础发布版本和公开底图试点草稿，不需要手工建表。

默认连接信息：

```text
地址：127.0.0.1:5432
数据库：medroute
用户：medroute
密码：medroute
```

如需修改，复制 `.env.example` 为 `.env` 后调整相应变量。

### 2.3 启动后端

命令行方式：

```bash
cd hospital-navigation-server
./mvnw spring-boot:run
```

IDEA 方式：

1. 打开仓库根目录或 `hospital-navigation-server`。
2. 将 Project SDK 和 Maven Runner JDK 设为 JDK 17。
3. 运行 `HospitalNavigationApplication`。

后端默认地址为 <http://127.0.0.1:8080>。

### 2.4 启动前端

新版前端首次使用时执行：

```bash
cd frontend
pnpm install
```

分别启动两个应用：

```bash
pnpm dev:admin
pnpm dev:navigation
```

打开：

- 电脑端维护后台：<http://127.0.0.1:5173/>
- 手机端导航验收：<http://127.0.0.1:5174/>

后端不是 8080 时，可通过查询参数指定：

```text
http://127.0.0.1:5173/?api=http://127.0.0.1:8082
http://127.0.0.1:5174/?api=http://127.0.0.1:8082
```

静态兼容页面仍可用 `python3 -m http.server 4173` 启动，作为迁移期间的验收基线。

## 3. 地图维护流程

### 3.1 新建草稿

1. 点击“新建草稿”。
2. 填写唯一草稿编码和修改说明。
3. 系统复制当前发布版本的楼层底图绑定和全部路网元素。

发布版本始终只读。误建草稿可点击“放弃当前草稿”，发布版本不会受影响。

### 3.2 替换每层底图

1. 选择目标楼层。
2. 点击“替换底图”，上传 PNG 或 JPEG。
3. 对比当前图和候选图，检查图片尺寸及 X/Y 坐标缩放比例。
4. 确认受影响的节点和 POI 数量，再执行替换。

单个文件上限 15 MB，总像素不得超过 5000 万。有未保存的路网修改时，维护端
会先阻止底图替换，必须保存草稿后再操作。

上传后系统按新旧图片宽高比例缩放该层节点和 POI 坐标。若新版底图改变了房间
布局或长宽比，维护端会显示非等比缩放警告；维护人员仍需逐点拖动核对，不能
只依赖自动缩放。

底图内容、修订信息和 SHA-256 均保存在 PostgreSQL 中，便于轻量部署时一次备份。

### 3.3 标注楼层路网

- “节点”：在地图上添加路线决策点。
- “路径”：依次选择两个同楼层节点，配置方向、耗时、距离和无障碍能力。
- “POI”：选择已有节点，添加可搜索目的地。
- “选择”：点击或拖动节点，并在右侧修改属性。

右侧属性区可修改节点坐标、路径端点/类型/使用范围、POI 绑定节点/标注坐标/
搜索词/使用范围和各元素启停状态。路径端点和 POI 绑定节点只能选择同一楼层节点。

删除节点前应先处理它引用的路径、POI 和电梯/楼梯停靠点。删除窗口会列出全部
阻断引用并提供“处理”入口；删除被启用关键路线引用的 POI 前，还必须先修改或
停用对应路线。所有删除都只修改草稿，保存并发布后才影响导航。

### 3.4 配置电梯和楼梯

1. 新建跨层设施，选择电梯或楼梯及无障碍能力。
2. 选择该设施和楼层。
3. 使用“停靠点”工具，将设施在该层绑定到一个路径节点。
4. 点击“配置跨层连接”，明确连接两个停靠点并填写耗时、方向和无障碍能力。

示例：

```text
A 电梯：1F 停靠点 <-> 3F 停靠点
B 电梯：1F <-> 2F，2F <-> 3F
A 楼梯：1F <-> 2F，2F <-> 3F
```

没有停靠点或跨层连接的楼层不可通过该设施到达。

### 3.5 维护 POI 搜索词

在 POI 属性中使用逗号分隔维护中文别名、完整拼音和拼音首字母，例如：

```text
检验, 抽血, jianyanke, jyk
```

移动导航页会同时匹配名称、编码、分类、楼层和这些关键词。正式数据应逐个确认
医院内部常用简称，不在前端自动生成拼音。

### 3.6 配置关键路线

1. 打开右侧“发布”页签。
2. 在“关键路线”区域点击“新增”。
3. 选择起点 POI、目的地 POI 和普通/无障碍模式。
4. 根据现场要求填写可选的最大距离和最大耗时。
5. 需要作为发布门禁时勾选“失败时阻止发布”。

关键路线使用 POI 稳定业务编码，因此复制草稿或发布新版本后无需重新绑定。删除、
停用或改名 POI 业务编码前，应先检查相关回归用例。关键路线配置发生变化后，现有
草稿必须重新执行校验。

测试数据预置入口到服务台、检验科、超声医学科，以及入口到超声医学科的无障碍
路线。执行“保存并校验”后，面板显示每条路线的通过状态、距离、耗时和实际使用
的楼梯或电梯。

V9 还为 `PILOT-DFSRMYY-001` 预置了 8 条停用的试点路线。完成逐层检查后再启用
这些路线，可与原有 4 条路线组成 12 条发布回归。完整步骤和现场核验边界见
[公开底图试点建图与验收清单](./12-公开底图试点建图与验收清单.md)。

### 3.7 生成固定点二维码

1. 打开右侧“运营”页签。
2. 在“固定点导航二维码”中选择当前发布 POI。
3. 点击“生成二维码”。
4. 确认导航页面基础地址，下载 PNG 或复制最终地址。

草稿、历史发布版本和停用 POI 不允许生成现场二维码。二维码中保存楼栋 ID 和
POI 稳定业务编码，不保存发布版本内的 POI 主键。也可以切换到当前发布版本，
在地图中选择 POI 后使用属性面板中的快捷按钮。

使用 `127.0.0.1` 或 `localhost` 启动时，弹窗会提示该地址只能在本机访问。手机
联调应将前端基础地址和 `api` 参数改为手机可访问的局域网地址；生产部署必须使用
正式 HTTPS 域名。

## 4. 校验、发布与回滚

### 4.1 发布前校验

完成编辑后：

1. 点击“保存草稿”。
2. 点击“保存并校验”。
3. 处理校验面板中的全部错误。

系统会检查引用关系、重复编码、坐标范围、POI 绑定、跨层连接、重要 POI
可达性、无障碍路线和全部启用的关键路线。草稿在校验后再次修改，或者关键路线
配置发生变化，原校验结果自动失效。

### 4.2 发布

校验通过后点击“发布版本”，填写现场复核和发布原因。发布事务会：

- 停用原发布版本。
- 将草稿变为只读发布版本并立即启用。
- 写入发布审计事件。
- 将仍生效且能按稳定公开 ID 匹配的临时封闭迁移到新版本。

发布后立即在导航页抽查入口到药房、检验科、影像科及跨层目的地。

### 4.3 回滚

在版本选择框中选择一个历史发布版本，点击“回滚启用此版本”并填写原因。
回滚只切换当前启用版本，不修改历史图内容；生效中的临时封闭也会按稳定公开 ID
迁移。新版本中不存在的目标不会被错误迁移。

## 5. 临时运营封闭

打开右侧“运营”页签，可立即停用：

- 整组电梯或楼梯设施。
- 某条楼层路径。
- 某条明确的跨层连接。

填写原因后封闭立即影响新路线。恢复时撤销对应记录，不需要重新发布地图。
当前 API 也支持有效起止时间，后台界面暂以立即生效、手工恢复为主。

## 6. 验收清单

- 三层分别显示正确底图，节点和 POI 没有明显偏移。
- A 电梯只连接已标注的 1F 和 3F，不会错误到达 2F。
- B 电梯和楼梯按各自连接关系跨层。
- 普通路线和无障碍路线均与现场通行规则一致。
- 电梯停用后路线切换到备选设施，恢复后切回较优路线。
- 草稿校验、发布、历史版回滚和草稿删除均可完成。
- 移动端可以按中文、拼音或首字母搜索 POI，并按楼层筛选。
- 移动端可以手动前后浏览路线步骤，跨层步骤会切换到对应楼层地图。
- 当前启用版本的固定点二维码可以下载，扫码地址包含正确楼栋和起点编码。
- 重启后端和数据库容器后，地图、版本和运营记录仍存在。
- 公开底图试点草稿中的 30 个 POI 均可从门诊入口规划普通和无障碍路线。

## 7. 备份与生产上线

数据库和底图可一起备份：

```bash
docker compose exec -T postgres \
  pg_dump -U medroute -d medroute > medroute-backup.sql
```

至少每日备份并定期做恢复演练。生产上线前还必须完成：

- 维护端统一登录、管理员角色和医院/楼栋数据权限。
- HTTPS、反向代理、受控 CORS 和请求审计。
- 数据库强密码、备份保留策略和监控告警。
- 真实医院底图授权、现场路线复核和固定回归路线。
