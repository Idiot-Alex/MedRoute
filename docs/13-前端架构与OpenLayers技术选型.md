# 前端架构与 OpenLayers 技术选型

## 1. 结论

新版前端采用：

| 范围 | 技术 | 职责 |
| --- | --- | --- |
| 工程 | Vue 3、TypeScript、Vite、pnpm workspace | 两个独立应用和共享包 |
| UI | Tailwind CSS | 布局、表单、工具栏和响应式界面 |
| 地图 | OpenLayers | 静态楼层底图、矢量路网、编辑交互和移动手势 |
| 图计算 | Spring Boot 后端 | 正式 Dijkstra 路线计算和发布版本约束 |

不采用前端路线计算库。移动端只提交起终点和路线模式，展示后端返回的楼层路线段
与跨层动作。

## 2. 选择 OpenLayers 的原因

当前地图不是地理坐标地图，而是：

```text
独立楼层位图
  + 像素坐标节点
  + 由节点 ID 连接的路径
  + 绑定节点的 POI
  + 电梯、楼梯停靠点和明确层间连接
```

OpenLayers 支持像素投影和静态图片，也原生提供 Feature 命中、选择、平移、
修改、绘制、吸附、图层和手机缩放手势。一套库可以同时服务维护端和导航端，
减少两套渲染器造成的坐标、样式和命中行为差异。

备选方案：

- Konva 适合高度定制的 Canvas 编辑器，但地图缩放、吸附和图数据关系需要更多
  自定义代码。如果 OpenLayers 编辑体验验证失败，再单独评估。
- Leaflet `CRS.Simple` 适合轻量只读查看，但编辑依赖额外插件，同时会引入第二套
  坐标和地图 API，不作为当前主方案。
- Fabric.js、Vue Flow 和 PixiJS 分别偏通用设计器、流程图和底层高性能渲染，
  与不可变底图上的导航图维护不匹配。
- MapLibre、IMDF 编辑器面向地理配准或室内墙体、房间矢量化，超出当前产品范围。

## 3. 工作区结构

```text
frontend/
├── apps/
│   ├── map-admin-web/
│   └── navigation-web/
├── packages/
│   ├── api-client/
│   └── map-core/
└── public/
```

`map-admin-web` 和 `navigation-web` 独立构建、独立发布。共享包只提供接口、领域
规则、坐标和地图基础能力，不共享具体页面布局。

## 4. 数据和坐标边界

后端 DTO 是唯一可持久化数据源。OpenLayers Feature 是视图模型，不能被序列化为
另一套草稿格式。

数据库使用楼层图片左上角为原点：

```text
dataX = imageX
dataY = imageY
```

OpenLayers 像素投影使用 Y 轴向上：

```text
mapX = dataX
mapY = imageHeight - dataY
```

正反转换统一位于 `packages/map-core/src/coordinates.ts`。路径只持久化
`fromNodeId` 和 `toNodeId`，显示几何由节点坐标生成。拖动节点时同步移动绑定 POI，
并重新生成相连路径。

## 5. Tailwind 边界

Tailwind 负责页面 UI，不负责 OpenLayers Canvas 内 Feature 的动态样式。

- 工具栏、表单、侧边栏、模式切换和移动布局使用 Tailwind。
- 节点、路径、POI、停靠点和路线使用 OpenLayers Style API。
- 保留 `ol/ol.css`，对地图容器内图片和 Canvas 明确设置 `max-width: none`，
  避免 Tailwind Preflight 改变地图资源尺寸。
- Tailwind 类名保持静态可分析，不拼接运行时类名。

采用 Tailwind 4 前，生产设备应满足 Chrome 111、Safari 16.4 或 Firefox 128
及以上。若宿主 App 使用更旧 WebView，需要降低版本或保留兼容 CSS。

## 6. 当前实现

已经完成：

1. pnpm 工作区和两个 Vue 应用。
2. 与 Java DTO 对齐的 TypeScript 类型和统一 API 客户端。
3. 真实三层公开测试底图的像素投影。
4. 节点、路径、POI、跨层停靠点分层显示。
5. 维护端节点新增、拖动、两节点吸附连边、POI 绑定和草稿保存。
6. 导航端起终点、常规/无障碍模式、后端路线调用、楼层路线段和跨层步骤。
7. 无后端 `demo=1` 演示模式。
8. 电梯和楼梯设施创建、停靠点标注、跨层连接和属性编辑。
9. 跨层关系本地检查，并区分“阻止草稿保存”和“发布前修复”问题。

当前不会替代静态维护后台。以下功能仍需迁移：

- 草稿创建、底图替换、校验、发布、回滚和关键路线回归
- 运营封闭和固定点二维码
- 移动端完整 POI 搜索、稳定业务编码深链和逐条导航模式

跨层关系采用显式建模：设施只包含它实际停靠的楼层，只有已配置的停靠点对才可
导航。电梯可以仅停 1F 和 3F，并直接维护 1F ↔ 3F 连接；系统不会根据楼层顺序
自动补出 2F。
