# 数据库设计

## 1. 适用范围与设计结论

本文定义 MedRoute 第一版可实施的 PostgreSQL 数据模型，并以
`09-多楼层导航实施方案.md` 为上位约束。

第一版采用以下结论：

- 使用 PostgreSQL，暂不依赖 PostGIS。地图坐标仍为楼层图片像素坐标。
- 以 `building_map_release` 作为路线图的发布和计算单位。
- 每层图片可以独立修订，但一次发布必须固定整栋楼所使用的图片、POI、节点、边和跨层连接。
- 草稿版本可编辑；已发布版本不可修改；一栋楼同一时刻只能有一个启用版本。
- 施工封路、电梯停运等临时状态不修改发布图，而是保存为带有效期的覆盖记录。
- 路线成本以 `time_seconds` 为主，`distance_meters` 只用于展示和校验。
- 当前轻量部署将底图资产保存在 PostgreSQL，确保地图数据可一次备份。

第一版不创建 PostGIS geometry 字段。将来需要真实地理坐标、院区室外路线或空间查询时，再通过独立迁移启用 PostGIS。

## 2. ID、编码、时间和单位约定

### 2.1 内部主键与公开 ID

- 所有表使用 `BIGINT GENERATED ALWAYS AS IDENTITY` 作为数据库内部主键。
- 对外暴露的资源使用由应用生成的 UUID `public_id`。
- `N1`、`P1`、`ELEV-A` 等 `code` 是人可读业务编码，不等同于数据库主键。
- 图元素的 `public_id` 和 `code` 在同一 `release_id` 内唯一。
- 复制上一版本为新草稿时，语义未变化的图元素保留 `public_id`；新元素生成新的 `public_id`。
- API 不返回内部自增主键。

本文 SQL 中的 `release_id` 是指向 `building_map_release.id` 的内部外键；
API 中的 `releaseId` 是同一记录的 `building_map_release.public_id`。应用仓储层负责二者转换。

### 2.2 时间与单位

- 所有业务时间使用 `TIMESTAMPTZ`，数据库和 API 均按 UTC 保存和传输。
- 时间成本统一使用整数秒，字段名为 `time_seconds`。
- 距离统一使用米，字段名为 `distance_meters`。
- `x`、`y` 是对应 `floor_map_revision` 图片上的像素坐标，原点为左上角。

### 2.3 方向

普通边和跨层边均显式保存 `direction`：

- `forward`：只能从 `from_*` 到 `to_*`。
- `both`：双向可通行。

反向单行边通过交换起终点后保存为 `forward`，不再额外使用 `reverse`。

## 3. 组织与地图版本表

### 3.1 hospital

```sql
CREATE TABLE hospital (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  public_id UUID NOT NULL UNIQUE,
  code VARCHAR(50) NOT NULL UNIQUE,
  name VARCHAR(100) NOT NULL,
  city VARCHAR(50),
  address VARCHAR(255),
  status VARCHAR(20) NOT NULL DEFAULT 'enabled'
    CHECK (status IN ('enabled', 'disabled')),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### 3.2 campus

```sql
CREATE TABLE campus (

  public_id UUID NOT NULL UNIQUE,
  hospital_id BIGINT NOT NULL REFERENCES hospital(id),
  code VARCHAR(50) NOT NULL,
  name VARCHAR(100) NOT NULL,
  address VARCHAR(255),
  status VARCHAR(20) NOT NULL DEFAULT 'enabled'

  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),

```

### 3.3 building

```sql
CREATE TABLE building (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  public_id UUID NOT NULL UNIQUE,
  campus_id BIGINT NOT NULL REFERENCES campus(id),
  code VARCHAR(50) NOT NULL,
  name VARCHAR(100) NOT NULL,
  status VARCHAR(20) NOT NULL DEFAULT 'enabled'
    CHECK (status IN ('enabled', 'disabled')),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (campus_id, code),
  UNIQUE (id, campus_id)

```

### 3.4 floor

```sql
CREATE TABLE floor (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  public_id UUID NOT NULL UNIQUE,
  building_id BIGINT NOT NULL REFERENCES building(id),
  code VARCHAR(20) NOT NULL,
  name VARCHAR(50) NOT NULL,
  level_no INT NOT NULL,
  status VARCHAR(20) NOT NULL DEFAULT 'enabled'
    CHECK (status IN ('enabled', 'disabled')),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (building_id, code),
  UNIQUE (id, building_id)
);
```

`code` 使用 `B2`、`B1`、`1F`、`2F` 等标准编码；`level_no` 只用于稳定排序，不用于推断电梯停靠关系。

### 3.5 floor_map_revision

一张楼层图片的每次修改都生成新修订版，原记录不可覆盖。

```sql
CREATE TABLE floor_map_revision (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  public_id UUID NOT NULL UNIQUE,
  floor_id BIGINT NOT NULL REFERENCES floor(id),
  revision_no INT NOT NULL CHECK (revision_no > 0),
  image_url VARCHAR(500) NOT NULL,
  image_width INT NOT NULL CHECK (image_width > 0),
  image_height INT NOT NULL CHECK (image_height > 0),
  mime_type VARCHAR(100) NOT NULL,
  sha256 VARCHAR(64) NOT NULL,
  created_by VARCHAR(100) NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (floor_id, revision_no),
  UNIQUE (id, floor_id)
);
```

当前实现通过独立的 `floor_map_asset` 表保存二进制内容，避免把大字段混入修订版
元数据和常规查询：

```sql
CREATE TABLE floor_map_asset (
  floor_map_revision_id BIGINT PRIMARY KEY
    REFERENCES floor_map_revision(id) ON DELETE CASCADE,
  content BYTEA NOT NULL
);
```

上传底图的 `image_url` 保存规范公开地址 `/api/map-images/{public_id}`。该公开接口
仅在修订版被当前启用的发布版本引用时返回图片，并使用 `Cache-Control: no-store`，
草稿和历史版本返回 `404`。维护工作区会把同一上传图片改写为
`/api/admin/map-images/{public_id}`，供维护端以私有不可变缓存预览；静态资源地址保持
不变。这样当前单实例部署可用一次 PostgreSQL 备份保存全部地图。未来底图规模或
访问量明显增加时，可以保持 `floor_map_revision` 和 URL 契约不变，将内容迁移至
对象存储。

### 3.6 building_map_release

```sql
CREATE TABLE building_map_release (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  public_id UUID NOT NULL UNIQUE,
  building_id BIGINT NOT NULL REFERENCES building(id),
  code VARCHAR(80) NOT NULL,
  status VARCHAR(20) NOT NULL DEFAULT 'draft'
    CHECK (status IN ('draft', 'published', 'retired')),
  is_active BOOLEAN NOT NULL DEFAULT false,
  content_revision BIGINT NOT NULL DEFAULT 0 CHECK (content_revision >= 0),
  based_on_release_id BIGINT,
  description VARCHAR(500),
  created_by VARCHAR(100) NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  published_by VARCHAR(100),
  published_at TIMESTAMPTZ,
  validated_revision BIGINT,
  validation_passed BOOLEAN,
  validated_route_regression_revision BIGINT,
  last_validated_at TIMESTAMPTZ,
  CHECK (NOT is_active OR status = 'published'),
  CHECK (
    (status = 'published' AND published_at IS NOT NULL AND published_by IS NOT NULL)
    OR status <> 'published'
  ),
  UNIQUE (building_id, code),
  UNIQUE (id, building_id),
  FOREIGN KEY (based_on_release_id, building_id)
    REFERENCES building_map_release(id, building_id)
);

CREATE UNIQUE INDEX uq_building_active_release
  ON building_map_release(building_id)
  WHERE is_active;
```

`based_on_release_id` 记录草稿从哪个版本复制而来。回滚不是修改旧版本内容，而是在事务中重新启用一个既有的 `published` 版本。

任何草稿图元素或楼层图片绑定发生变化时，应用都必须在同一事务中递增
`content_revision`。维护端通过它实现 `If-Match` 乐观锁，发布服务也用它确认校验结果没有过期。

### 3.7 release_floor_map

该表固定一次楼栋发布中每层所使用的图片修订版。

```sql
CREATE TABLE release_floor_map (
  release_id BIGINT NOT NULL,
  building_id BIGINT NOT NULL,
  floor_id BIGINT NOT NULL,
  floor_map_revision_id BIGINT NOT NULL,
  PRIMARY KEY (release_id, floor_id),
  FOREIGN KEY (release_id, building_id)
    REFERENCES building_map_release(id, building_id),
  FOREIGN KEY (floor_id, building_id)
    REFERENCES floor(id, building_id),
  FOREIGN KEY (floor_map_revision_id, floor_id)
    REFERENCES floor_map_revision(id, floor_id)
);
```

所有图元素必须引用 `release_floor_map(release_id, floor_id)`，因此不会引用未包含在该版本中的楼层。

## 4. 发布版本内的图元素

### 4.1 path_node

```sql
CREATE TABLE path_node (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  release_id BIGINT NOT NULL,
  floor_id BIGINT NOT NULL,
  public_id UUID NOT NULL,
  code VARCHAR(80) NOT NULL,
  x DOUBLE PRECISION NOT NULL CHECK (x >= 0),
  y DOUBLE PRECISION NOT NULL CHECK (y >= 0),
  node_type VARCHAR(30) NOT NULL DEFAULT 'normal'
    CHECK (node_type IN ('normal', 'decision', 'poi_access', 'connector_stop')),
  enabled BOOLEAN NOT NULL DEFAULT true,
  remark VARCHAR(255),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  FOREIGN KEY (release_id, floor_id)
    REFERENCES release_floor_map(release_id, floor_id),
  UNIQUE (release_id, public_id),
  UNIQUE (release_id, code),
  UNIQUE (id, release_id),
  UNIQUE (id, release_id, floor_id)
);
```

### 4.2 path_edge

`path_edge` 只表示同一楼层内的通行边。跨楼层通行必须使用 `vertical_link`。

```sql
CREATE TABLE path_edge (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  release_id BIGINT NOT NULL,
  floor_id BIGINT NOT NULL,
  public_id UUID NOT NULL,
  code VARCHAR(80) NOT NULL,
  from_node_id BIGINT NOT NULL,
  to_node_id BIGINT NOT NULL,
  time_seconds INT NOT NULL CHECK (time_seconds > 0),
  distance_meters NUMERIC(10, 2) NOT NULL CHECK (distance_meters >= 0),
  direction VARCHAR(20) NOT NULL DEFAULT 'both'
    CHECK (direction IN ('forward', 'both')),
  edge_type VARCHAR(30) NOT NULL DEFAULT 'walk'
    CHECK (edge_type IN ('walk', 'corridor', 'door', 'ramp', 'virtual')),
  access_scope VARCHAR(20) NOT NULL DEFAULT 'public'
    CHECK (access_scope IN ('public', 'staff')),
  accessible BOOLEAN NOT NULL DEFAULT true,
  base_status VARCHAR(20) NOT NULL DEFAULT 'enabled'
    CHECK (base_status IN ('enabled', 'disabled')),
  remark VARCHAR(255),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  CHECK (from_node_id <> to_node_id),
  FOREIGN KEY (release_id, floor_id)
    REFERENCES release_floor_map(release_id, floor_id),
  FOREIGN KEY (from_node_id, release_id, floor_id)
    REFERENCES path_node(id, release_id, floor_id),
  FOREIGN KEY (to_node_id, release_id, floor_id)
    REFERENCES path_node(id, release_id, floor_id),
  UNIQUE (release_id, public_id),
  UNIQUE (release_id, code),
  UNIQUE (id, release_id)
);
```

把 `floor_id` 放在边上并使用组合外键，可以从数据库层保证普通边的两个端点属于同一发布版本和同一楼层。

### 4.3 poi

```sql
CREATE TABLE poi (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  release_id BIGINT NOT NULL,
  floor_id BIGINT NOT NULL,
  public_id UUID NOT NULL,
  code VARCHAR(80) NOT NULL,
  node_id BIGINT NOT NULL,
  name VARCHAR(100) NOT NULL,
  category VARCHAR(50) NOT NULL,
  keywords TEXT[] NOT NULL DEFAULT '{}',
  x DOUBLE PRECISION NOT NULL CHECK (x >= 0),
  y DOUBLE PRECISION NOT NULL CHECK (y >= 0),
  access_scope VARCHAR(20) NOT NULL DEFAULT 'public'
    CHECK (access_scope IN ('public', 'staff')),
  accessible BOOLEAN NOT NULL DEFAULT true,
  enabled BOOLEAN NOT NULL DEFAULT true,
  remark TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  FOREIGN KEY (release_id, floor_id)
    REFERENCES release_floor_map(release_id, floor_id),
  FOREIGN KEY (node_id, release_id, floor_id)
    REFERENCES path_node(id, release_id, floor_id),
  UNIQUE (release_id, public_id),
  UNIQUE (release_id, code),
  UNIQUE (id, release_id)
);
```

POI 的 `x/y` 是标签或图标位置；实际路线从其绑定的 `node_id` 进入图。

## 5. 跨楼层设施

### 5.1 vertical_connector

设施本体只表达“这是哪一部电梯/楼梯/扶梯”，不自动表达它经过哪些楼层。

```sql
CREATE TABLE vertical_connector (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  release_id BIGINT NOT NULL REFERENCES building_map_release(id),
  public_id UUID NOT NULL,
  code VARCHAR(80) NOT NULL,
  name VARCHAR(100) NOT NULL,
  connector_type VARCHAR(30) NOT NULL
    CHECK (connector_type IN ('elevator', 'stair', 'escalator')),
  access_scope VARCHAR(20) NOT NULL DEFAULT 'public'
    CHECK (access_scope IN ('public', 'staff')),
  accessible BOOLEAN NOT NULL DEFAULT true,
  base_status VARCHAR(20) NOT NULL DEFAULT 'enabled'
    CHECK (base_status IN ('enabled', 'disabled')),
  remark VARCHAR(255),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (release_id, public_id),
  UNIQUE (release_id, code),
  UNIQUE (id, release_id)
);
```

### 5.2 connector_stop

```sql
CREATE TABLE connector_stop (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  release_id BIGINT NOT NULL,
  connector_id BIGINT NOT NULL,
  floor_id BIGINT NOT NULL,
  node_id BIGINT NOT NULL,
  public_id UUID NOT NULL,
  stop_code VARCHAR(80) NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  FOREIGN KEY (connector_id, release_id)
    REFERENCES vertical_connector(id, release_id),
  FOREIGN KEY (node_id, release_id, floor_id)
    REFERENCES path_node(id, release_id, floor_id),
  UNIQUE (release_id, public_id),
  UNIQUE (release_id, stop_code),
  UNIQUE (connector_id, floor_id),
  UNIQUE (id, release_id, connector_id),
  UNIQUE (id, release_id)
);
```

一个设施在一个楼层最多有一个停靠点；如果同一电梯组在同层有多个独立入口，应拆成不同设施，或在后续版本显式扩展停靠点模型。

### 5.3 vertical_link

```sql
CREATE TABLE vertical_link (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  release_id BIGINT NOT NULL,
  connector_id BIGINT NOT NULL,
  public_id UUID NOT NULL,
  code VARCHAR(80) NOT NULL,
  from_stop_id BIGINT NOT NULL,
  to_stop_id BIGINT NOT NULL,
  time_seconds INT NOT NULL CHECK (time_seconds > 0),
  distance_meters NUMERIC(10, 2) NOT NULL DEFAULT 0
    CHECK (distance_meters >= 0),
  direction VARCHAR(20) NOT NULL DEFAULT 'both'
    CHECK (direction IN ('forward', 'both')),
  access_scope VARCHAR(20) NOT NULL DEFAULT 'public'
    CHECK (access_scope IN ('public', 'staff')),
  accessible BOOLEAN NOT NULL DEFAULT true,
  base_status VARCHAR(20) NOT NULL DEFAULT 'enabled'
    CHECK (base_status IN ('enabled', 'disabled')),
  remark VARCHAR(255),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  CHECK (from_stop_id <> to_stop_id),
  FOREIGN KEY (connector_id, release_id)
    REFERENCES vertical_connector(id, release_id),
  FOREIGN KEY (from_stop_id, release_id, connector_id)
    REFERENCES connector_stop(id, release_id, connector_id),
  FOREIGN KEY (to_stop_id, release_id, connector_id)
    REFERENCES connector_stop(id, release_id, connector_id),
  UNIQUE (release_id, public_id),
  UNIQUE (release_id, code),
  UNIQUE (id, release_id)
);
```

只有 `vertical_link` 明确连接的停靠点之间才可通行。不能根据电梯编号或楼层顺序自动补边。

## 6. 临时运营覆盖

表名沿用 `edge_state_override`，但允许覆盖楼层内边、跨层边或整个垂直设施。

```sql
CREATE TABLE edge_state_override (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  public_id UUID NOT NULL UNIQUE,
  building_id BIGINT NOT NULL,
  release_id BIGINT NOT NULL,
  target_type VARCHAR(30) NOT NULL
    CHECK (target_type IN ('path_edge', 'vertical_link', 'vertical_connector')),
  path_edge_id BIGINT,
  vertical_link_id BIGINT,
  vertical_connector_id BIGINT,
  status VARCHAR(20) NOT NULL DEFAULT 'closed'
    CHECK (status = 'closed'),
  effective_from TIMESTAMPTZ NOT NULL,
  effective_to TIMESTAMPTZ,
  reason VARCHAR(500) NOT NULL,
  created_by VARCHAR(100) NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  revoked_by VARCHAR(100),
  revoked_at TIMESTAMPTZ,
  CHECK (effective_to IS NULL OR effective_to > effective_from),
  CHECK (
    (target_type = 'path_edge'
      AND path_edge_id IS NOT NULL
      AND vertical_link_id IS NULL
      AND vertical_connector_id IS NULL)
    OR
    (target_type = 'vertical_link'
      AND path_edge_id IS NULL
      AND vertical_link_id IS NOT NULL
      AND vertical_connector_id IS NULL)
    OR
    (target_type = 'vertical_connector'
      AND path_edge_id IS NULL
      AND vertical_link_id IS NULL
      AND vertical_connector_id IS NOT NULL)
  ),
  FOREIGN KEY (release_id, building_id)
    REFERENCES building_map_release(id, building_id),
  FOREIGN KEY (path_edge_id, release_id)
    REFERENCES path_edge(id, release_id),
  FOREIGN KEY (vertical_link_id, release_id)
    REFERENCES vertical_link(id, release_id),
  FOREIGN KEY (vertical_connector_id, release_id)
    REFERENCES vertical_connector(id, release_id)
);
```

运行时生效条件：

```text
release_id = 当前路线所用发布版本
revoked_at IS NULL
effective_from <= 当前时间
effective_to IS NULL 或 effective_to > 当前时间
```

`closed` 覆盖只会排除边或设施，不会把发布图中 `base_status = disabled` 的元素重新开放。恢复通行通过撤销覆盖完成。

发布或回滚时，系统将仍生效的覆盖按目标稳定 `public_id` 重新绑定到目标版本，
并撤销来源版本上的旧覆盖。目标版本中不存在同一公开 ID 时不迁移，避免因业务编码
复用而误封新边。生产版可在切换确认页额外列出未能迁移的覆盖。

## 7. 反馈与发布审计

### 7.1 route_feedback

```sql
CREATE TABLE route_feedback (

  FOREIGN KEY (start_poi_id, release_id)
    REFERENCES poi(id, release_id),
  FOREIGN KEY (end_poi_id, release_id)
    REFERENCES poi(id, release_id)
);
```

### 7.2 release_validation_run

```sql
CREATE TABLE release_validation_run (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  release_id BIGINT NOT NULL REFERENCES building_map_release(id),
  content_revision BIGINT NOT NULL CHECK (content_revision >= 0),
  passed BOOLEAN NOT NULL,
  result JSONB NOT NULL,
  checked_by VARCHAR(100) NOT NULL,
  checked_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

`result` 保存校验器版本、错误码、元素公开 ID 和说明。发布操作只能使用最新一次成功且图数据未再变更的校验结果；实现时可通过草稿 `updated_at` 或内容校验和判断。

### 7.3 building_route_regression_case

关键路线配置属于楼栋，使用稳定 POI 业务编码跨发布版本解析，不引用某个版本中的
临时 POI 主键。

```sql
CREATE TABLE building_route_regression_config (
  building_id BIGINT PRIMARY KEY REFERENCES building(id),
  revision BIGINT NOT NULL DEFAULT 0 CHECK (revision >= 0),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE building_route_regression_case (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  public_id UUID NOT NULL UNIQUE,
  building_id BIGINT NOT NULL REFERENCES building(id),
  code VARCHAR(80) NOT NULL,
  name VARCHAR(120) NOT NULL,
  start_poi_code VARCHAR(80) NOT NULL,
  end_poi_code VARCHAR(80) NOT NULL,
  route_mode VARCHAR(30) NOT NULL
    CHECK (route_mode IN ('normal', 'accessible')),
  critical BOOLEAN NOT NULL DEFAULT TRUE,
  enabled BOOLEAN NOT NULL DEFAULT TRUE,
  max_distance_meters NUMERIC(10, 2),
  max_estimated_seconds INTEGER,
  created_by VARCHAR(100) NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_by VARCHAR(100) NOT NULL,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (building_id, code),
  CHECK (start_poi_code <> end_poi_code),
  CHECK (max_distance_meters IS NULL OR max_distance_meters > 0),
  CHECK (max_estimated_seconds IS NULL OR max_estimated_seconds > 0)
);
```

校验草稿时，服务端在当前草稿中按 `start_poi_code` 和 `end_poi_code` 查找启用
公共 POI，再使用与正式导航相同的图模型、Dijkstra 成本和通行策略执行。关键
用例失败进入校验错误，非关键用例失败进入提醒。新增、修改、删除配置后，楼栋内
全部草稿的旧校验状态必须失效，防止使用配置变更前的成功结果发布。
草稿保存的 `validated_route_regression_revision` 还必须与配置表当前 `revision`
相同。校验、配置修改和发布通过配置行锁串行化，避免并发操作绕过该检查。

### 7.4 building_release_event

```sql
CREATE TABLE building_release_event (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  building_id BIGINT NOT NULL REFERENCES building(id),
  from_release_id BIGINT,
  to_release_id BIGINT NOT NULL,
  event_type VARCHAR(20) NOT NULL
    CHECK (event_type IN ('publish', 'rollback')),
  operated_by VARCHAR(100) NOT NULL,
  reason VARCHAR(500),
  operated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  FOREIGN KEY (from_release_id, building_id)
    REFERENCES building_map_release(id, building_id),
  FOREIGN KEY (to_release_id, building_id)
    REFERENCES building_map_release(id, building_id)
);
```

## 9. 发布、回滚与读取事务

### 9.1 发布

发布操作必须在一个数据库事务中完成：

1. 锁定目标 `building` 行，防止并发发布。
2. 确认目标版本为 `draft`，且最新成功校验的 `content_revision` 等于当前草稿版本。
3. 将当前启用版本的 `is_active` 改为 `false`。
4. 将目标版本改为 `published`，填写发布人和发布时间，并设为启用。
5. 写入 `building_release_event`。
6. 提交后使导航图缓存失效。

任何一步失败都回滚。已发布版本中的 `release_floor_map` 和图元素不得再执行更新或删除。

### 9.2 回滚

回滚同样在事务中切换 `is_active`，不复制、不修改历史版本。回滚后新路线使用被重新启用版本；已经返回给客户端的路线仍通过其 `releaseId` 可追溯。

### 9.3 导航读取

一次路线请求必须先读取楼栋当前启用版本 ID，再以该固定 `release_id` 加载完整图、POI 和当前生效覆盖。请求处理中即使发生新发布，本次结果仍基于开始时确定的版本，并在响应中返回该 `releaseId`。

## 10. 发布前数据校验

数据库约束之外，发布服务至少执行：

- 每层恰好选择一个 `floor_map_revision`。
- 节点和 POI 坐标位于所选图片宽高范围内。
- 每个启用 POI 绑定同发布版本、同楼层的启用节点。
- 普通边的端点存在、耗时为正且不会跨楼层。
- 停靠点属于正确设施，垂直连接两端属于同一设施。
- 不根据楼层顺序隐式补全电梯或扶梯连接。
- 所有业务编码和公开 ID 在版本内唯一。
- 入口、挂号处、药房、电梯、楼梯等重要 POI 在普通模式下可达。
- 无障碍模式排除楼梯和所有 `accessible = false` 的边、设施及 POI。
- 草稿不存在孤立的必需节点、重复边和失效引用。
