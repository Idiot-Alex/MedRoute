# 医院室内导航总体设计方案

## 1. 项目定位

本项目面向公司陪诊业务，目标是建设一套支持多医院的室内路线引导平台。

系统不追求实时定位，不依赖 GPS、Beacon、UWB、二维码、Wi-Fi 指纹等外部定位能力，而是基于医院楼层图和人工维护的路径网络，实现关键点到关键点的路线规划。

典型问题：

- 从挂号处怎么去检验科？
- 从检验科怎么去药房？
- 从门诊楼怎么去住院部？
- 应该乘哪个电梯上楼？
- 轮椅患者应该走哪条路线？

## 2. 为什么不做实时定位

医院室内环境存在以下限制：

- GPS 基本不可用。
- PDR 纯手机惯导误差累积严重。
- 医院通常不允许随意贴二维码。
- 医院通常不允许部署 Beacon/UWB 等设备。
- 医院内部磁场、楼层、电梯环境复杂。
- 用户真正需要的是“路线怎么走”，不是厘米级定位。

因此本系统将重点放在：

```text
固定关键点 + 室内地图 + 路径规划 + 分步路线说明
```

而不是实时定位。

## 3. 总体架构

```text
医院楼层示意图
      ↓
地图制作/标注
      ↓
POI + PathNode + PathEdge
      ↓
PostgreSQL
      ↓
Spring Boot 导航服务
      ↓
Dijkstra 路径规划
      ↓
H5 / 小程序 / App WebView
      ↓
地图高亮 + 分步指引
```

## 4. 核心模块

### 4.1 医院管理

用于管理多家医院。

包括：

- 医院名称
- 城市
- 院区
- 楼栋
- 楼层
- 地图版本

### 4.2 楼层地图管理

每层楼对应一张楼层示意图。

第一阶段可直接使用 PNG/JPG 图片。

后续可支持：

- SVG
- CAD 转图片
- PDF 转图片
- 矢量地图

### 4.3 POI 管理

POI 是用户能搜索和选择的关键点。

例如：

- 挂号处
- 收费处
- 药房
- 检验科
- 影像科
- 电梯
- 楼梯
- 卫生间
- 护士站
- 自助机
- 报告打印点

### 4.4 路径节点管理

路径节点是路线计算使用的图节点。

它们通常位于：

- 走廊拐点
- 路口
- 电梯口
- 楼梯口
- 科室门口
- 大厅入口
- 长走廊中间点

### 4.5 路径边管理

路径边连接两个路径节点。

每条边可以包含：

- 长度
- 预计耗时
- 是否无障碍
- 是否室内
- 是否可用
- 是否施工封闭
- 是否员工通道
- 路线备注

### 4.6 跨楼层连接

电梯、楼梯、扶梯是特殊边。

例如：

```text
门诊楼 1F 电梯A
        ↓
门诊楼 3F 电梯A
```

系统中可以建成一条 connector edge。

### 4.7 路径规划

第一版使用 Java 实现 Dijkstra。

原因：

- 医院室内图规模不大。
- Java 实现灵活。
- 方便加入业务规则。
- 不必第一版引入 pgRouting。
- 每层图片坐标系独立，像素距离不能作为跨层 A* 的可靠启发函数。

### 4.8 前端展示

前端负责：

- 显示楼层示意图
- 显示 POI
- 高亮路径
- 展示分步文字
- 切换楼层
- 起点/终点选择

可选技术：

- MapLibre GL JS
- Leaflet
- 原生 Canvas
- SVG

第一版 Demo 推荐使用 HTML + SVG/Canvas，降低复杂度。

当前正式多楼层页面使用楼层位图 + SVG 路网。未来建立统一米制坐标或需要室外
地理路线时，再评估 MapLibre GL JS。

## 5. 推荐技术栈

| 模块 | 推荐 |
|---|---|
| 后端 | Java + Spring Boot |
| 数据库 | PostgreSQL + Flyway；暂不启用 PostGIS |
| 路径规划 | Java Dijkstra |
| 前端 | H5 / 小程序 / App WebView |
| 地图渲染 | 楼层位图 + SVG |
| 建图工具 | 自研 Web 地图维护后台 |
| 数据格式 | 发布图工作区 JSON |

## 6. 第一版 MVP

第一版以一栋三层门诊楼为范围。

功能：

- 每层上传独立楼层图并配置 POI、节点和路径边
- 配置电梯、楼梯的实际停靠点和跨层连接
- 创建草稿、校验、发布和回滚完整楼栋导航图
- 设置临时路径或设施封闭
- 选择跨层起终点，计算路线并按楼层高亮
- 展示跨层动作和分步说明

暂不做：

- 实时定位
- PDR
- 蓝牙 Beacon
- UWB
- Wi-Fi 指纹
- AR 导航
- 跨楼栋和院区室外路线
- 复杂多级审批

## 7. 多医院扩展思路

数据层必须从一开始支持：

```text
hospital_id
campus_id
building_id
floor_id
map_version_id
```

这样后续可以支持几十家医院，而不是只给单医院定制。

## 8. 核心结论

本项目本质是：

```text
多医院室内路径知识库 + 路线引导平台
```

不是传统 GPS 导航，也不是实时定位系统。
